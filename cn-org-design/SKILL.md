# 编制房建工程施工组织设计

## 总体原则

- 以正式受控项目资料为事实源，以企业目录和样文为编制逻辑源；样文中的项目数据和做法不得直接移植。
- 先核实项目事实，再确定施工部署，最后编制施工方法。不得先写通用文本再回填项目名称。
- 成品必须是针对目标项目的成熟施组，不得用“按图执行”“另详专项方案”“通过计算确定”等表述代替本文件应给出的拟定做法。
- 项目没有的内容必须删除，项目有的内容必须增加；同类专业的编制深度保持一致。
- 只交付用户要求的文件类型。用户要求 Word 时，只交付 `.docx`，渲染图、PDF和审计日志仅作内部验证。

## 工作流程

### 1. 建立资料清单与版本边界

1. 递归清点用户提供的施工图、勘察、合同、清单、进度、样文、企业制度、审查意见和设计回复。
2. 记录每项资料的文件名、版本日期、专业、单体和用途；识别正式版、作废版及冲突版本。
3. 优先使用正式施工图和明确的企业要求。样文只提供章节逻辑、写作深度和表达方式。
4. 需要操作 Word、PDF、CAD 或表格时，调用相应的文档、PDF、CAD、表格技能；必须完整读取被调用技能的说明。
5. 缺失信息不会改变总体方案时，采用工程经验形成明确的拟定做法，并在具体数据处作醒目的待核标识；缺失信息会显著影响结构安全、危大工程或主要功能时，停止定稿并提出最少量关键问题。

### 2. 深读图纸并建立项目事实矩阵

按单体和专业提取并交叉核对：

- 建设地点、建设单位、总建筑面积、单体数量、层数、高度、结构体系、基础形式和抗震信息。
- 地形高差、地质、水文、湿陷性、地基处理、基坑深度和周边环境。
- 混凝土等级、抗渗等级、钢筋和型钢、砌体、屋面、门窗、保温、防水、防渗、防腐和装修做法。
- 给排水、暖通、电气、消防、工艺设备、预留预埋、设备基础、地下管网与管廊接口。
- 各单体差异。不同单体参数不同则分别表达，不得用一个“通用值”覆盖。

形成“事实—来源—适用单体—章节去向—状态”矩阵。区分：

- 已核实事实；
- 可追溯计算或图纸推导；
- 施工组织拟定值；
- 待核实值。

不得在正文中反复插入统一免责声明。待核实值只在出现处着色或高亮，并写明具体待核事项。

### 3. 建立目录和章节内容模型

1. 采用企业规定的十五章目录和标题名称。
2. 把样文逻辑、提示词要求和项目实际合理融合，不做机械“强制覆盖”。
3. 先输出章节—子章节—必写内容—图表—材料设备—资料来源矩阵，确认无缺项后再扩写正文。
4. 每章只承担一个管理或技术目的；把项目概述放在工程概况，把组织机构放在施工部署，把进度横道图放在施工进度计划。

### 4. 编制施工部署与资源组织

明确：

- 项目组织机构、岗位职责、目标管理和总承包管理；
- 施工区段、流水顺序、关键线路、专业穿插和单体开工顺序；
- 劳动力、材料、机械、周转料具、测量装置、技术文件和资金计划；
- 临建设施、临水临电、道路、堆场、排水、消防和总平面管理；
- 总进度安排、横道图及保证措施。

组织机构图和管理体系图必须使用可编辑的 Word 原生形状、文本框、连接符或可编辑表格，不得以不可编辑截图代替。

### 5. 编制主要施工方案及技术措施

对每个实际存在的分部分项工程，至少写清：

1. 适用范围与施工条件；
2. 材料及技术要求；
3. 人员、机械和仪器；
4. 工艺流程；
5. 施工方法；
6. 关键参数与拟定做法；
7. 质量标准和检查方法；
8. 安全、环保和消防控制；
9. 异常处置；
10. 成品保护。

只保留“施工方法”，不得再设置与其内容重复的“分步作业与记录”。提到材料、构配件、设备或仪器时，必须列出名称、规格或性能要求、进场验收、复试或检定要求；不得只写工艺动作。

DDC 地基处理、深基坑、工业厂房、废水处理中心、防渗防腐、地下管廊等关键专业必须采用相同的完整深度，不得一项详写、另一项一笔带过。详见深度规则参考文件。

### 6. 编制管理策划和计划

完整编制施工平面布置、资源计划、施工进度计划、检验试验计划、质量策划、环境文明施工、职业安全、季节性施工、科技创新和施工方案编制计划。

不得把风险名称、材料清单、机械清单或职责名称逐行裸列成正文。根据信息关系选择：

- 对比、责任、频次、标准和资源配置用表格；
- 先后关系用编号步骤；
- 管理层级用可编辑组织图；
- 少量并列控制点用完整句式。

总进度计划发生替换或调整时，不得只换横道图。必须以最新计划为唯一进度基准，提取总工期、分区和单体起止日期、关键节点、关键线路、近关键线路和资源峰值，并同步核对编制依据、项目目标、施工部署、资金计划、劳动力计划、机械计划、第八章、季节性施工、第十五章及待核事项。劳动力峰值必须与临水、临电、消防、生活区和临建设施计算采用同一口径。

进度横道图信息密集时，单独设置 A3 横向节，图前图后恢复 A4 纵向；同一横道图不得重复插入。横道图自身已有完整标题时，不再另设占页标题。详见进度联动参考文件。

### 7. 数据与内容校核

逐项执行 [content-review-checklist.md](references/content-review-checklist.md)：

- 核对图纸与正文、单体之间、章节之间和表图之间的数据一致性；
- 删除目标项目不存在的工艺；
- 补齐目标项目实际存在的工艺；
- 检查材料、设备、参数、质量、安全、验收和成品保护是否齐全；
- 检查是否存在套话、凑字数、同义重复、章节重复和模糊甩项。

对每项危大工程明确范围、拟定措施、监测、验收、停工条件和法定程序。法定专项方案或专家论证要求可以写，但不得取代施组中的总体施工方法和具体控制参数。

### 8. 创建 Word 并进行原生排版

1. 使用独立的正文、各级标题、表题、图题、表头、表格正文和附表样式。
2. 正文、附表、图表标注、标题层级、封面和页边距按企业规则设置。
3. 表格采用固定布局、页面可用宽度、重复表头、行不跨页和单元格垂直居中。对齐规则按项目/企业要求执行；本项目交付惯例为首行表头居中加粗、正文全部左对齐。
4. 表格内不得继承“正文”样式，单元格一律使用表格专用样式，且表内样式必须统一：
   - 首行统一为一种表头样式（表格表头/附表表头），居中加粗由样式本身提供；
   - 正文统一为一种左对齐样式（表格正文（…左对齐）/附表正文（左对齐）/表内文字），同一表内不得混用“居中”与“左对齐”样式名；
   - 居中样式改左对齐按同族映射（常规/紧凑/特宽/附表各自字号行距），不跨族改字号行距；
   - 不得用直接格式（直接对齐/加粗/缩进）覆盖样式：Word 样式面板仍显示原样式名，会被视为“格式不统一”。
5. 表格内段落清除正文继承的首行缩进（firstLine/firstLineChars），内容按对齐规则靠左或居中排布。
6. 目录必须是可更新的 Word TOC 域，并在结果文本中保留最近一次核实的页码。
7. 页眉、页脚、报审表、封面、组织图、横道图和总平面图分别做版面检查。

### 9. 双重验收

先运行：

```bash
python scripts/audit_docx.py /absolute/path/to/output.docx
```

发生进度计划替换时，再运行：

```bash
python scripts/audit_schedule_linkage.py /absolute/path/to/output.docx \
  --start YYYY-MM-DD --finish YYYY-MM-DD --peak N
```

修复全部 `ERROR`；逐项处理 `WARNING`。

审计脚本同时检查：表格样式是否表内统一（首行一种表头样式、正文一种左对齐样式）、单元格是否有直接格式残留、是否存在未定义的样式引用。

再用 Microsoft Word 原生打开 QA 副本：

1. 更新整个目录和全部域；
2. 检查样式面板：同一表内单元格样式名统一（首行显示表头样式、正文显示左对齐样式），点选单元格确认工具栏对齐方式与样式一致，无直接格式覆盖；
3. 检查封面、报审表、目录、工程概况表、组织图、横道图、关键技术章节、附表和末页；
4. 检查表格是否越界、数字拆行、表头过窄、行高失控、页眉错位或图片丢失；
5. 保存 QA 副本后，比较保存前后的表格数、图片数、媒体字节数和关系文件；
6. 只有结构资源无损时才允许替换正式文件。若 Word 回存导致图片或对象丢失，丢弃该回存副本，保留已验证的正式文件，并让目录域在打开时更新。

不得只凭应用内预览、LibreOffice 或 PDF 渲染判断 Word 排版正确。

调整表格对齐、行高、缩进或统一样式会引起分页页数增减，属正常现象；交付前向用户说明预期页数变化，不视为排版错误。

## 输出与停止条件

仅在以下条件全部满足后交付：

- 章节齐全且名称符合企业目录；
- 项目事实可追溯，单体差异已表达；
- 实际工程内容无缺项，不适用内容已删除；
- 施工方法具有材料、设备、参数、质量、安全和异常处置深度；
- 无明显重复、凑字数和模糊甩项；
- DOCX 审计无错误；
- Microsoft Word 原生抽检通过；
- 只交付用户要求的 Word 文件。

若重大数据冲突、正式图纸缺失或危大工程关键参数无法可靠拟定，停止正式定稿，输出最小待补资料清单。
